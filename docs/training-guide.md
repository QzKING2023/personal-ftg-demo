## 启动与操作

Godot 4.5.1 打开 `project.godot` 后按 F5（960×540 固定镜头设计）。运行时 R 重置场景；修改 `.tres` 后须退出游戏并重新运行，R 不保证绕过资源缓存。

| 操作 | 物理输入 |
| --- | --- |
| 移动、蹲下 | A/D 或 ←/→；S 或 ↓（蹲姿原地锁定，不可蹲行） |
| 跳跃 | Space 或 ↑；与前/后组合为 9/7，上下同时按中和 |
| 动作 A/B/C/D | U/I/K/J |
| 236C，面向右 | S → S+D → D，再按 K |
| 236C，面向左 | S → S+A → A，再按 K |
| 214C，面向右 | S → S+A → A，再按 K |
| 214C，面向左 | S → S+D → D，再按 K |
| j214D（空中） | 起跳后同 214 相对搓招 + J |
| 站防、蹲防、空防 | 相对后 4、下后 1；空中 4/1 均为空防 |
| 前冲、后撤 | 相对 66/44，两段间至少一帧中立 |
| 普通投 | I+K，两个新按下相差 ≤3 物理帧且配齐时按住；中心距离 ≤64px |
| 木桩防御 | G 循环 无 → 站防 → 蹲防 → 空防（逐帧确定性请求；木桩无自主决策） |

物理 D 是「向右」，动作 D 对应物理 J；方向数字按面向折算。I/K 单键最多多等 3 个物理帧配对（方向解析在按下当帧、配对只推迟起手）；U/J 直出。命中后 8 个物理帧冻结、输入仍采样；动作缓存 0–5 有效；命中确认取消年龄 0–8。跳跃为准备 4f、空中 38f、落地基础 3f+空技 1f；j2D 命中路径经落地例外在恢复首帧消费 214C（唯一例外，其余空技落地首帧一律锁）。

## 确定性验收入口

全量验收用编排器（推荐 sweep 模式：先枚举全部 job 的唯一 Solver 请求、跨进程去重算完入缓存、再热跑全部 job）：

```powershell
python tools/run_acceptance.py --sweep --output .scratch/ftg-character-implementation/acceptance/<新目录>
```

`tools/run_acceptance.ps1` 为串行旧入口（无缓存环境、会计入全部 job 冷成本），仅作历史兼容；报告同时检查退出码与脚本错误。单套件定向运行沿用逐进程独立 APPDATA 约定：

```powershell
$env:APPDATA = "$PWD/.scratch/<目录>/runtime-<套件>"
& D:/Godot/Godot_v4.5.1-stable_mono_win64_console.exe --headless --path . -s res://tests/test_<套件>.gd
```

训练场测试注入 Godot 输入映射并推进物理帧；它不等于真人按键，也不测外设延迟。回放数据与站位边界见 [solver-guide.md](solver-guide.md)。

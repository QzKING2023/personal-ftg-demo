# 角色招式基线：实施路径与阶段启动提示词

日期：2026-09-23  
状态：建议执行路径；本文交付计划与提示词，不代表已创建实施票据或完成代码验收。  
目标：将已确认的角色招式基线落到共享招式资源、确定性战斗会话、训练场和 Combo Solver，并取得自动回放与真人试玩证据。

## 1. 从哪里开始

从**阶段 0：核对实施差异**开始。角色定位和逐招职责已经确定，接下来只补齐影响实现的规则细节，再发布规格、拆票和逐票实现。

推荐顺序：

**差异核对 → 规则与调校初值 → 正式规格与拆票 → 普通地面链 → 被防取消与 Rekka → slide 捞起与换边 → 击飞与空中出口 → 空中 D 系与落地 → 弹地与循环边界 → 联合验收和真人调校。**

第一条可玩切片采用 `5A > 5B > 5C > 5D`。此前建议直接从 `236C > 5D` 开始，会同时引入 slide、真实位移、特殊取消来源和换边；本计划将其移到基础地面链之后，降低首票的耦合。

## 3. 阶段 0：核对实施差异

### 工作与完成条件

逐条将当前设计映射到代码和资源，标为已实现、部分实现、待实现或待决策。重点核对：

- HitProfile 已交付能力，以及旧票据中的人工复核项。
- 普通地面链、蹲姿绑定、`5C` 取消 launcher 职责、旧招式迁移。
- 木桩被防路径：现有玩家防御不能自动证明“玩家攻击被木桩防住”；需要确定性防御请求或训练设置。
- 三类取消窗口、蓄力 `5[D]`、Rekka 首次分支锁定、`236C` 来源限定的 `5D → 5B`。
- 真实位移、身体穿越、垂直判定框偏移、面向和方向候选锁定。
- slide、低浮空后倒地、弹地、带落地，以及独立修正。
- Solver 对恢复后的普通连接、真实空间状态、输入蓄力与特殊状态的搜索能力。
- 旧 pre-jump 必杀取消、Solver JSON 导出和蹲姿复玩事项；只纳入相关依赖，引用原票据。

完成标准：每条缺口都有证据来源与建议阶段；没有把历史“未实现”描述当作当前事实，也没有把历史通过记录写成本轮实测。

## 4. 阶段 1：补齐实施语义与调校初值

### 工作与完成条件

使用 `grill-with-docs`，仅处理阶段 0 找到的阻塞问题。已接受的招式职责、命中/被防资格和无 OTG 边界直接继承。

| 需要落定的内容 | 必须能回答的问题 |
| --- | --- |
| 输入与取消 | 蓄力开始、阈值、松键和 Hitstop 如何计时？Rekka 输入如何与 B+C 组合等待仲裁？三类窗口与特殊来源资格何时失效？ |
| 防御 | 被防硬直、推退、停顿如何声明？用哪些明确的反击动作和距离验证“安全/不安全”？ |
| 运动与换边 | 位移在哪些动作帧发生？如何在命中帧判定穿越、受墙截断和身体碰撞？每帧朝向与冲刺方向锁定如何共存？ |
| 状态转换 | `236C` 落地何时转 slide、何时结束？`2C` 低浮空如何转倒地？`j2D` 带落地与 `214C~C` 空中命中如何处理？ |
| 落地例外 | `j2D → 214C` 是否涉及落地首帧、输入何时可缓存、在哪一帧消费？通用首帧锁与专用例外的精确关系是什么？ |
| 弹地 | 何时触地、何时反弹、何时可追击？可追击弹地与不可追击普通倒地如何区分？ |
| 修正 | 起手等级锁定、逐击累计、伤害与时间/轨迹分别怎样计算和舍入？A 起手断链与 B 级以上有限延长如何体现？ |
| 数值初表 | 各招帧数、伤害、命中框位置/大小、运动、受击计时与取消窗口的首轮值是什么？ |

初值用于启动实验，不宣称最终平衡。语义问题先解决；只能靠手感或空间实验判断的数值，记录假设和可执行观察标准即可。

涉及 ADR 的变化需记录：ADR-0003 的首版范围需要扩展到 slide/弹地；ADR-0002 的旧伤害衰减与连段结束描述需要核对新的起手修正、普通连接和有限 loop。明确保留自然恢复与不设全局命中/时长上限的原则，不能把允许多圈误写成允许无限循环。

完成标准：本轮实施范围内无阻塞行为问题；新增字段有单位、时间基准、必填/默认和非法组合；数值初值与待试玩项分开；真实架构变化通过 domain-modeling 记录 ADR 或后继决策。

## 5. 阶段 2：发布规格与拆分票据

### 工作与完成条件

先用 `to-prd` 汇总为新目录的 `spec.md`，再用 `to-issues` 建立 `issues/`。各技能要求的方案核对集中在完整草案之后完成；沿用已经确认的规则，不重新访谈角色定位。

规格至少覆盖：逐招输入与属性、取消矩阵、状态转换和同帧顺序、起手与累计修正、字段校验、旧资源迁移、代表路线正反例、防御和空间验收、Solver 能力边界。

拆票时给出候选顺序：普通命中链 → 蹲姿普通技和低浮空 → 被防链 → Rekka → slide 捞起 → 蓄力和换边 → `6A` 空中链 → `6D/2D` 出口 → 空中 D 系落地 → 弹地 → 综合调校。按实际共用行为调整，不按“先所有数据、再所有运行时”拆分。

普通起手修正随最早的连段切片加入；新状态的修正随着各状态实现同步延续，不能拖到最后才决定循环是否合理。每个新状态都同时补充 Solver 状态描述与循环去重依据。

完成标准：每票可独立回放或演示，有正反例和明确依赖；所有纳入基线的招式都被覆盖；已完成事项没有重复票；旧资源迁移后的 manifest 始终可加载。未知参数不得靠 schema 默认值偷偷决定。

## 7. 阶段 4：被防取消、Rekka 与扫倒路线

先用确定性木桩防御请求或训练设置建立“玩家攻击被防”的真实结算路径，再实现接触驱动的链式/必杀取消。木桩仍无自主决策。防御硬直、推退和停顿按已确认规格执行。

Rekka 验证首个派生请求锁定、延迟窗口、B+C 仲裁、地空资料差异和普通恢复后的连接。安全性结论必须注明反击招式、时机和距离；单纯存在防御硬直字段不算验收。

完成标准：被防普通链允许，挥空拒绝；被防不能借用 jump cancel、`236C → 5D` 或命中专用出口。`214C~B` 地面普通倒地、空中延长，`~C` 收尾均与规格一致。

## 8. 阶段 5：ground slide、蓄力位移与换边

**演示目标：** `236C > 5D/5[D] > 5B` 在规定条件成立；中板蓄力、版边普通 `5D`、手动 `665B/665C` 分别验证。

建议拆成至少两个可演示小票：先交付有限 slide 与来源限定的捞起链，再交付蓄力、完整位移、碰撞穿越和换边。每票使用自身明确初值，最终重新联合验证。

必须验证：

- `236C` 地面命中为浮空后 slide，空中命中使用普通空中资料；两者都在命中时取得特殊取消资格。
- `5D` 在前置浮空与 slide 中命中都可覆盖原状态；挥空后原轨迹继续。
- `5D → 5B` 来源资格按规格建立、消费与清除，不能泄漏给普通 `5D`。
- 只有命中且实际穿过才换边；被防、挥空、墙截断保留正确位置关系。

## 12. 阶段 9：联合验收、可读反馈与真人调校

### 验收顺序

1. 对照规格逐招检查 manifest、稳定 id、输入绑定、profile、取消目标、属性、运动和数值版本。按迁移方案处理旧 `214D/jD`，保留历史测试的意义与来源。
2. 补齐训练场必要反馈：当前招式、目标状态、被防/命中、修正与失败原因；用原生形状体现徒手和短刀、位移起落及收刀节拍。正式美术、音效和完整动画另开范围，不阻塞本轮行为验收。
3. 按路线矩阵回放，包含左右面向、中板/版边、近远距离、地空目标、A/B 起手、命中/被防/挥空与窗口首末帧。按招式实际相关性选组合。
4. 执行全量自动化和训练场 smoke；文档与新资源同步更新。
5. 用户实际试玩，记录输入容错、短刀节奏、换边后指令、空中追击和收尾反馈；包含旧蹲姿修复的复玩。
6. 每轮只调整有明确目的的参数组，记录修改前后及受影响路线复验。规则改变回到 decisions/spec，数值改变同步 frame-data 和资源。

全量检查示例，在项目根目录运行，并为每次验收使用新的输出目录：

```powershell
./tools/run_acceptance.ps1 -Output '.scratch/ftg-character-implementation/acceptance/final-01'
```

引擎路径按现有脚本配置使用，必要时传入 `-Engine`。报告同时检查退出码和脚本错误；测试数量不是固定完成标准。

## 13. 如何使用这些提示词

- 现在复制阶段 0 提示词即可；阶段 0–2 是实施准备，不自动启动后续编码。
- 设计收敛、规格和拆票尽量放在同一任务中；阶段 1 已确定的答案由文档承接，后续不重复追问。
- 实施阶段每次执行一个无阻塞票据。可以在新任务中重复该阶段提示词；代理从本地票据读取上下文和真实完成证据。
- 票据状态遵循 [本地 tracker](agents/issue-tracker.md) 与 [triage 标签](agents/triage-labels.md)。标签不能替代验收清单；实现完成、自动化通过和待真人确认分别记录。
- 只有遇到现有训练场无法隔离的设计问题才使用 `prototype`；独立目录实验通过 `handoff` 带入问题、带回结论。本计划不强制额外原型阶段。
- 本文阶段顺序是实施建议；行为规则以正式设计和已接受决策为准。若执行时事实有变化，先更新差异与依赖，再继续受影响阶段。

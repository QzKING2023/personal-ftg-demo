# FTG Demo MVP 规划

## 目标

在 Godot 4.5 中快速验证一套横向格斗的基础手感：进入单一训练场后，玩家可以左右移动、跳跃、使用一种招式，命中木桩，并看到清晰的受击反馈。美术只使用 Godot 原生形状绘制，玩家角色和木桩共用形状结构、通过颜色区分。

## 已确定的范围

- 2D 横向固定镜头，键盘操作。
- 使用 GDScript，优先缩短从空项目到可玩的反馈周期。
- 单一场景；一个玩家角色、一个木桩。
- 玩家能力：左右移动、跳跃、基础招式。
- 木桩：静态、可受击，不做 AI。
- 受击反馈：命中判定、生命值变化、短暂硬直或击退、可重复测试。
- 攻击采用固定的 startup / active / recovery 窗口；一次按键最多对同一目标造成一次命中。
- 首版不限制时长，不做回合制胜负。
- 首版不做角色美术资产、复杂动画、音效、联网或手柄适配。

## MVP 验收标准

1. 启动项目后自动进入训练场，不需要额外配置。
2. 玩家能在舞台边界内稳定移动并跳跃，落地行为可预测。
3. 按下攻击键时，攻击范围和持续时间一致；靠近木桩时能命中，远离时不会误命中。
4. 木桩被命中后至少有两种可见反馈：生命值变化，以及短暂颜色/位移/硬直反馈。
5. 玩家可连续攻击、移动和跳跃进行手感测试；重置场景后状态恢复。
6. 全部角色与场景视觉元素都由原生绘制形状组成，替换颜色不会影响玩法。

## 建议实施顺序

1. **可运行场景**：主场景、固定镜头、地面和舞台边界、输入映射。
2. **玩家移动**：水平移动、重力、跳跃、落地与边界约束。
3. **招式与命中**：一个攻击状态、攻击碰撞范围、木桩受击检测。
4. **受击反馈**：生命值、硬直/击退、颜色闪烁或短暂停顿、重置入口。
5. **手感调整**：移动速度、跳跃高度、攻击前摇/持续时间、击退距离等参数化。
6. **清理与记录**：补齐运行说明，记录当前参数和已知限制，再决定是否进入 AI 或第二种招式。

## 暂定输入

窗口先按 960×540 规划，保持单场景固定镜头；如果实际测试显示比例或视野不合适，再调整。

| 行为 | 默认键 |
| --- | --- |
| 左右移动 | A / D 或方向键 |
| 跳跃 | Space |
| 攻击 | J |
| 重置 | R |

输入应集中在 Godot 的 Input Map 中，具体按键可在实现时调整。

## 暂不决策的问题

- 是否加入防御、闪避、蹲下或第二种招式。
- 木桩是否需要生命值归零后的消失/重生表现。
- 是否加入简单 HUD、音效和屏幕震动。
- 何时把木桩替换成最小 AI；这应在基础招式手感稳定后再评估。

## 下一阶段已确认方向

- 体验定位为“短流程展示”：重点展示玩家角色的动作、招式节奏和木桩的受击反馈。
- 范围继续限于一名玩家角色、一个木桩和一个训练场，不加入 AI 或胜负回合。
- 玩家角色暂以“特殊追击窗口”为核心机制；OTG、地面弹跳和墙反弹是可选的表现形式，具体采用哪一种由后续连段设计确定。
- 玩家角色需要相对完整的招式表与连段语义；短流程展示限制体验时长，不删减为单一路线。允许多个绑定到具体招式的短方向序列，Space 独立并按招式配置支持 jump cancel。
- 操作采用四个动作键 A/B/C/D，方向键和 Space 另算；四键的具体招式分工在连段结构确定后展开。
- 连段先锁定两条拓扑：稳定路线为“地面起手 → 地面连接 → 地面收尾”，进阶路线为“地面起手 → 浮空 → 浮空追击 → 空中路线 → 空中收尾”；收尾作为路线终点，因为其后没有有效追击条件。
- 主路线只允许命中确认取消；动作键输入可缓存最多 6 个物理帧并在取消窗口消费。方向序列采用独立的、适合人类操作的输入历史窗口，不与动作键缓存共用 6 帧上限。
- 伤害按连段命中数递减，最低保留 10%；不额外设置硬直最低值、全局击飞/下落速度上限或最大命中数/总时长上限，连段应由招式受击状态自然恢复而中断。
- “连段收尾”因后续没有有效追击条件而成为路线终点，不主动定义木桩立即恢复或清除受击状态。
- 木桩支持中立、地面受击硬直、浮空受击和倒地处理；硬直归零即自然受身并断连，落地后恢复中立。训练反馈显示连段命中数和木桩当前状态，不增加额外断连提示。
- `Combo Solver` 先作为开发期的连段验证与帧数调整工具，不预设为运行时战斗系统。
- 设计澄清将先确定核心机制与连段规则，再决定是否需要超出轻量状态机、招式数据和集中战斗结算的架构。

## 下一步原型目标

制作一个只验证规则与手感的可玩切片：使用 A/B/C/D、方向序列和独立 Space，跑通一条稳定地面路线与一条浮空/空中路线；同时显示连段命中数和木桩状态。原型必须验证动作键 6 帧缓存、独立方向序列窗口、命中优先于落地的同帧顺序、jump cancel、自然受身断连、10% 伤害下限，以及 `Combo Solver` 对循环接续的检测。通过这些验证后再调整具体招式帧数和反馈表现。

# 验收提速:并行编排、前缀恢复与跨进程缓存

Status: ready-for-agent

## Problem Statement

全量验收(`run_acceptance` 的完整 job 集)的耗时随 Solver 路线膨胀持续恶化:票据 06 时约 2 小时,票据 07 时实测 5.64 小时,当前规模估计 10-15 小时。开发者在每次票据推进后都被迫把验证挂在后台按小时轮询,一个"改一行、验一次"的迭代周期被拉成过夜;项目进度被验收时间卡死。

耗时结构已查明:全量 ≈ 30 个唯一重 Solver 请求 × 每个约 1000 秒;前 8 个 job 占 96% 耗时但没有单一 job 超过 25%;而 runner 以严格串行方式在 24 逻辑核的机器上一次只跑满一个核。每个唯一请求内部,从 frame 0 的全量重放(`_run_schedule` 每次新建会话)在延迟叶子、边探测、缺口枚举、路线行进多处反复发生,是路线膨胀转化为耗时的乘法机制。

## Solution

以 ADR-0006 的机械等价纪律为纲,分三阶段交付,每阶段独立过差分门,搜索语义全部冻结:

1. **Python 并行编排器**:顶替现有 PowerShell runner,保持输出契约完全同构(summary.json 同 schema、runner 状态文件、同一失败谓词、规范 job 序),import 先行栅栏后以默认并发 8 扇出测试 job,保留串行模式作为差分基线。墙钟时间从"全部 job 之和"降为"最长 job"量级。
2. **实测引导的前缀恢复**:先插桩测量每个唯一请求的耗时分解(延迟叶子/边探测/缺口枚举/路线重放),然后把已过差分证明的 CombatSession clone/restore seam 接入重放热点——延迟搜索每个向量叶子从共享前缀快照恢复、只喂尾部输入,而不是从 frame 0 重放;profile 显示其他重放点占大头时,用同一机制追加扩展。
3. **跨进程结果缓存**:把现有的请求级完整结果缓存(带 descriptor 全等校验与全源码语义签名)持久化到机器本地;job 启动只读加载、写独立 fragment、编排器收尾合并。迭代重跑(改测试或非战斗代码)在缓存命中下趋近于零 Solver 耗时。
4. **全局前置清扫分片**(票据 08,2026-10-02 grilling 由条件票转正):import 栅栏后先以枚举模式把全部 job 快速过一遍(每 Solver 请求只记 descriptor、不计算,分钟级),收集全局唯一请求 descriptor 集(跨 job 去重);唯一请求铺满并发车道并行算完写缓存 fragment(复用 06 基建),合并后所有 job 以热缓存正常跑。饱和是结构性的(平坦计算清单天然填满车道),墙钟模型 = 枚举(分钟级) + Σ唯一请求耗时/并发 + Σ热跑轻 job。

成功判据:全量冷跑 ≤ 1 小时(由最终一次真实全量运行证明);分片不再以"最长 job >20 分钟"为触发条件——用户要求 8 核饱和,并为未来连段边增长保持 ≤1h 余量(2026-10-02);执行顺序 ②票据 04 → ③票据 06 → 分片票据 08 → 终证票据 07。

## User Stories

1. 作为开发者,我想让全量验收的 job 以默认并发 8 分布到多个核,以便墙钟时间由最长 job 而不是全部 job 之和决定。
2. 作为开发者,我想让 import job 先单独完成、测试 job 之后才并发,以便共享的导入缓存目录不被并发写坏。
3. 作为开发者,我想保留一个串行模式开关,以便随时生成差分基线,证明并行没有改变任何验收结果。
4. 作为开发者,我想让编排器产出与旧 runner 同构的 summary.json 与退出码状态文件,以便现有失败谓词与验收惯例一行不改。
5. 作为开发者,我想 summary.json 保持规范 job 序(import → 字母序测试 → diagnose_inputs → main-smoke)而不是完成序,以便与串行基线逐行 diff。
6. 作为开发者,我想每个并行 job 拥有独立的 APPDATA/LOCALAPPDATA 与 runtime 目录,以便并行进程互不污染。
7. 作为开发者,我想并发数可调,以便给同时进行的日常开发留出核数。
8. 作为开发者,我想先插桩测量每个唯一 Solver 请求的耗时分解(延迟叶子/边探测/缺口枚举/路线重放),以便前缀恢复投在真正的大头上,而不是凭直觉押注。
9. 作为开发者,我想让延迟搜索的每个向量叶子从共享前缀快照恢复而不是从 frame 0 全量重放,以便前缀成本每次搜索只付一次。
10. 作为开发者,我想快照同时覆盖会话状态与求解器侧计数器(帧号、物理帧、已验证命中数、失败原因积累、循环快照序列),以便恢复后的报告编号与文案与全量重放一字不差。
11. 作为开发者,我想字典序延迟枚举、budget 按叶子计数、proof_mode 逐圈快照重现、首条成立即返回、失败代表性排序全部保持不变,以便提速不改变任何搜索结论与首达路线。
12. 作为开发者,我想有一个差分 harness 在样本链上并跑新旧两条路径、逐叶子比较完整 run dict(含 break_kind、失败文案、verified 计数、快照序列),以便任何恢复偏差当场被抓而不是潜伏到全量。
13. 作为开发者,我想在 profile 显示边探测或路线重放占大头时,用同一套前缀共享机制扩展到那些重放点,以便用已验证的手段拿到剩余收益而不再发明新机制。
14. 作为开发者,我想让请求级结果缓存持久化到机器本地文件并在 job 启动时加载,以便同表重跑跳过全部已证明请求。
15. 作为开发者,我想每个并行 job 只写自己的缓存 fragment、run 结束由编排器合并进规范文件,以便全程无锁且并发安全。
16. 作为开发者,我想缓存命中校验沿用 descriptor 规范文本全等(不只比摘要),以便过期或碰撞条目不可能被误用。
17. 作为开发者,我想战斗脚本、招式表、引擎版本任一变化都自动使相关缓存条目失效,以便任何命中都可信。
18. 作为开发者,我想保留 --acceptance-no-reuse 基线模式,以便随时证明缓存没有改变任何结果。
19. 作为开发者,我想查明最重测试此前零缓存计数的原因(禁用还是统计被重置),以便持久化对它生效,或明确记录它为何豁免。
20. 作为开发者,我想票据级验证只跑被触动的定向 test job 加各自的差分 harness,以便每张票的验证以分钟计而不是小时计。
21. 作为开发者,我想全量冷跑目标由最终一次真实运行证明,以便"≤1 小时"有据可查而不是估计。
22. 作为开发者,我想在 06 之后把全部 job 的唯一请求全局去重后按 descriptor 扇出到多进程并行计算(全局前置清扫),以便全量期间 8 核饱和、并为未来连段边增长保持 ≤1h 余量(2026-10-02 由条件票转正)。
23. 作为维护者,我想所有提速手段限定为机械等价变换(并行、前缀共享/恢复、结果缓存)并各自过差分门,以便验收的证明力从不被速度交换。
24. 作为维护者,我想语义削减(减少延迟候选、循环圈数、观测帧数、空间档位)被明确禁止并记录在案,以便未来没有人"顺手优化"掉证明力。
25. 作为设计者,我想 Solver 报告的全部内容(接续边、配置缺口、路线、循环、镜像结论、文案)在提速前后逐 fingerprint 相等,以便我对规则结论的既有信任不需要重建。
26. 作为维护者,我想缓存文件留在本机且被 gitignore,以便仓库不携带派生物、也不出现跨机器的陈旧凭据。

## Implementation Decisions

- **编排器**:Python 单文件 CLI,取代现有 PowerShell runner;参数至少含引擎路径、输出目录、并发数(默认 8)、串行开关、缓存文件路径。job 集合与规范序、失败谓词(非零退出码或正数 script_errors,计数缺失按 0 处理不产生假失败)、每 job 独立 APPDATA/LOCALAPPDATA、日志落盘方式与旧 runner 对齐。
- **环境事实**:机器仅有 Windows PowerShell 5.1(无 pwsh 7);Python 可用;24 逻辑核、31.5GB 内存。PS1 的 GBK/UTF-8 BOM 坑对新编排器不再适用,但后台运行、退出码落盘、以输出文件行数判活的既有惯例保留。
- **profile 插桩**:扩展 Solver metrics 输出,按延迟叶子/边探测/缺口枚举/路线重放分类报告耗时;插桩本身零语义影响,是阶段 2 的准入数据。
- **前缀恢复**:快照点取首个可调链接最早生效帧之前;恢复内容包括 CombatSession 的 clone_state 与求解器侧 frame/physics/verified/失败积累/循环快照计数;每个叶子的尾部输入按该叶子的延迟向量重新编译;与 proof_mode(逐圈快照)和票据 08 的 unpredicted_tail(尾部放行)模式兼容。调度记忆化(边探测/路线行进的前缀共享)是条件性追加票,由 profile 数据触发,机制与差分门同型。
- **缓存**:持久化对象是现有请求级缓存的 entries 全集(descriptor + 报告快照);加载只读、写入 per-job fragment、编排器收尾合并;默认开启,基线模式保留;存放于仓库本地 gitignore 的缓存目录。快照/恢复(_freeze_report/_thaw_report)与语义签名(战斗脚本逐文件哈希、引擎版本、限额常量)均为现有机制的直接复用。
- **执行顺序**:①并行编排器 → ②profile + 前缀恢复(含条件性扩展)→ ③跨进程缓存 → ④全局前置清扫分片(08)→ ⑤终证(07)。顺序依据:缓存对冷跑首遍的贡献被 08 的清扫前置化(去重发生在 job 开跑之前);清扫复用 06 的 fragment 基建,故在 06 之后。原顺序依据中"缓存对冷跑首遍几乎零贡献"仅适用于无清扫形态,已被 08 修正。
- **全局前置清扫(票据 08)**:三段式(枚举 → 清扫 → 热跑);枚举模式为编排器专用开关(不进验收参数,先例 = 04 隐藏开关),miss 记 descriptor 并返回拒绝形态 stub、命中返回真实报告,枚举跑产物全部丢弃;worker 按 descriptor 重算写 fragment(descriptor 全量含表与选项,重建纯机械);热跑 miss 就地现算兜底正确性,misses>0 记为枚举缺口(性能债);summary mode 记 `acceptance-sweep`;`--acceptance-no-reuse` 蕴含禁用清扫。
- **验证经济学**:编排器自身等价用快 job 子集对拍(覆盖有/无 metrics、import、diagnose、main-smoke 全部输出形态);Python 串行全量跑一次作为唯一基线;此后所有差分门对该基线;全量仅在最终证明时再跑一次。

## Testing Decisions

- **只测外部行为**:编排器在输出契约层测试(summary.json 逐字段、状态文件、退出码、日志可解析性),不测内部调度细节;Solver 改动在 run dict 与 report fingerprint 层测试,不测私有函数;缓存在冷/热等价与失效行为层测试。
- **等价 oracle(两级制,ADR-0006 修订四)**:Tier A 同模式对拍(冷对冷:并行对串行、插桩前后、04 前缀恢复)——compare_summaries 全字段相等,排除集仅计时测量字段,`*_runs` 计数与 `combo_cache` 必须相等;Tier B 跨模式对拍(去重/热跑/清扫 vs 冷串行基线)——在全字段相等上追加排除 `combo_cache`/`solver_profile`/`mode`(及 `appdata`),另加不变量(各 Solver job `hits+misses==calls`、清扫热跑 misses 记录、`report_fingerprints` 含 keys 请求序键逐字段相等);Solver 内部改动另加逐叶子完整 run dict 比较。
- **差分 harness 先例**:CombatSession 前缀恢复 seam 的差分测试(多序列 × 每帧切分 × 多种恢复目标 × 逐帧六维比较 + 变异验证)是阶段 2 harness 的直接先例;两轮变异验证(故意损坏一个快照字段必须被抓到)同样适用于新 harness。
- **门清单**:编排器子集对拍门、并行对串行全量门、旧路径对新路径逐叶子门、缓存冷热门、最终全量 ≤1h 证明。每个门失败即回退,不放松谓词。

## Out of Scope

- 语义削减:减少延迟候选、循环圈数、观测帧数、空间档位;修改 Solver 搜索语义(字典序、budget、proof_mode、首条成立即返回、失败排序)。
- 削减 job 数、断言数或测试内容;测试套件重构。
- 升级 pwsh 7、迁移 CI/云端、跨机器共享缓存。
- CombatSession 语义或战斗规则的任何变更。

# 17: 普通投、投距失败与拆投

**What to build:** 玩家在地面站立自由行动且处于投距内时输入 B+C 执行普通投，并能在规定窗口内拆投；不满足状态或距离时输入失败且不回退拳脚。

**Blocked by:** 16: 蹲下与站防、蹲防、空防

**Status:** ready-for-human

- [x] B+C 在 ≤3f 组合容差内且两键仍按住时覆盖单键选择，投距内启动普通投；面向决定投向。
- [x] 普通投 startup 固定 5f，拆投窗口从首个 startup 帧开始并在投发生后延续 10f；有效拆投阻止投结果并产生日志/事件。
- [x] 蹲下、pre-jump、空中、招式阶段、受击硬直和落地恢复中不执行普通投。
- [x] 投距外失败，不启动普通投，也不回退普通拳脚；失败原因可观察。
- [x] 真实键盘路径与逐帧 CombatSession 测试覆盖成功、距离失败、禁用状态和拆投边界。

## Comments

**2026-09-16 实现验收记录（agent）**

- 输入载体（`frame_input.gd`）：`pressed_action_keys`/`held_action_keys` 承载同帧多键与持键状态（组合配对与「配齐帧仍全部按住」的唯一依据）；`dummy_tech_request` 为木桩拆投请求（测试/验证驱动，训练场不设置——与 issue 16 木桩攻击请求同一口径）。`action_key` 变为兼容属性：getter 按 D>C>B>A 折算同帧单键（表外注入键原样透传），赋值等价于单键按下并按住。
- B+C 组合识别（`combat_session.gd` 输入阶段）：成员键按下时检查搭档 ≤3 个物理帧内未消费的新按下且两键当帧都按住——配齐即消费两个按下记录、记录组合意图并当帧尝试执行；首键提前松开、仅有长期按住或超出容差都不配对（分别回落为单键路径）。同帧 B+C+D 由组合覆盖 D，投距外/禁用状态失败不回退任何单键。成员键集合收敛到 `MoveData.THROW_COMBINATION_KEYS`（会话与 Solver 共用）。
- 单键组合等待：表内含投时 B/C 单键在配对窗口（按下 +3 物理帧）内只是缓存候选（诊断可见、不消费方向、不参与消费仲裁），窗口末帧按单键处理——保留原按下帧的姿态锁定、方向匹配锚点与缓存起龄点，此时才消费所锁定的方向历史；等待按物理帧推进（Hitstop 不合并相隔超 3 帧的两键、也不冻结等待到期）。非成员键（A/D）不等待，按其输入帧正常处理。
- 投执行门与结果：仅地面站立、可自由行动可投（蹲下/pre-jump/空中/招式阶段/受击与防御硬直/落地恢复一律禁用——空跳恢复第 2、3 帧的攻击例外不适用）；投距 = 身体中心水平距离 ≤ 资源 `throw_range`（64px，含边界）且身体矩形垂直重叠。startup 5f（F1 = 配齐帧，投发生在第 5 帧 = ACTIVE 起点）；拆投窗口 = 投帧 1..15（`active_to`，投发生 + 延续 10f）；未拆投时窗口关闭当帧一次性成立结果——木桩沿投向击退（240px/s）并进入地面受击硬直（20f），打断木桩进行中的攻击，不造成 HP 伤害、不进入连段计数；收招后回中立，木桩稍后自然受身。停顿中配齐只记录意图，恢复首个正常帧尝试一次，仍禁用或投距外即拒绝并结束请求（之后不补投、不等待进入投距、不回退 B/C），更新的动作输入覆盖待处理意图。
- 拆投：窗口内的 `dummy_tech_request` 当帧打破投（THROW_TECHED 事件、玩家回中立、木桩不受任何投结果影响）；同帧拆投先于结果判定，末帧（F15）拆投仍成立，F16 起请求无效。已知的未定义边缘：投进行中若玩家被木桩命中触发停顿，停顿帧内的拆投请求不被记录（消费阶段在冻结帧不运行）——规格未定义该交互，按确定性静默丢弃处理。
- 事件与可观察性：`CombatEvent` 新增 THROW_HIT（投向见 direction）/ THROW_TECHED / THROW_FAILED（原因枚举 STATE/RANGE，投距外与禁用状态的失败原因可观察）；诊断快照新增 `held_action_keys`（原始按住记录）、`pending_combination`（停顿内的组合意图）、`throw_window_left`（投拆投窗口剩余帧）。训练场诊断行新增 按住/投窗/待投 列，键位提示补「投 I+K = B+C」，投结果触发木桩闪烁，投技不显示命中框（`player_attack_rect()` 非打击招式返回空矩形）。
- 数据与校验：新增 `data/moves/BC.tres`（5/11/10，投距 64，B+C 组合无单键绑定）并入共享 manifest——训练场、会话默认表与 Solver 同步获得普通投。MoveTable 新增两条领域校验（spec 未逐条列出、按「普通投 startup 5f、约 15f 拆投窗口是领域规则不由资源覆盖」延伸）：投技 `active_frames` 必须为 投发生 1f + 延续 10f = 11f（窗口与相位单一来源）；每表至多一个投技（B+C 组合无单键/层级/记法维度，并列即无确定性选择）。投结果数值（硬直 20f、击退 240）在 GameParams（`THROW_HITSTUN_FRAMES`/`THROW_KNOCKBACK`/`THROW_COMBINATION_TOLERANCE`/`THROW_TECH_WINDOW_AFTER_GRAB`）——投技 schema 不含伤害/击退字段，参数集中符合「手感数值集中在 GameParams」。
- 连锁时序更新：默认表含投后 B/C 单键 +3f 等待改变了共享表路径的确定时序，~30 个既有默认表测试按新时序更新（如地面路线 5A→5B→5D 命中 6/19/32、完整空中路线命中 9/23/42/55/67、5B→214D 命中 8/23）；注入表（无投）不受影响。Solver 时序模型同步：B/C 命中预测计入组合等待——命中当帧按下（w=0）的等待与随后的停顿重叠、于恢复首个正常帧消费（延迟 1），其余按下延迟 3；`wait_to` 标注按窗口减等待收窄（下限 0）。默认表 9 条接续边全部有效、循环判定不受影响（注入回边周期 27→30、53→54）。

# 21: Solver 循环证明与有限空中资源

**What to build:** Solver 区分有限空中资源造成的断链与真实可重复循环，并以逐圈状态回放提供可复核证明。

**Blocked by:** 20: Solver 完整路线与时序验证

**Status:** ready-for-human

- [x] 状态去重包含影响未来结算的姿态、阶段、招式帧、面向、速度、受击、连段、缓存、方向候选、落地和 jump 标记。
- [x] 空中滞空和落地资源不能自动续期；真实回边须由逐圈状态快照重现后才报告为循环。
- [x] 8 圈、2400 帧、240 帧恢复观测和 40 帧空中延迟上限达到时报告截断/未完成观测，不宣称完整证明。
- [x] 报告包含循环路径、起始状态、逐帧输入和证明结果，并保持确定性排序。

## Comments

**2026-09-17 实现验收记录（agent）**——改动集中于 `scripts/combat/combat_session.gd`（新增 `settlement_state()`）与 `scripts/combat/combo_solver.gd`（循环证明语义 + 观测上限上报 + 循环报告材料），新增 `tests/test_solver_cycles.gd`，更新 `tests/test_combo_solver.gd` 两处旧断言与 README 测试清单。

- **全量状态去重键**：`CombatSession.settlement_state()` 只读快照覆盖双方姿态/阶段（含蹲下/防御/冲刺/木桩招式）、当前招式及招式帧（含命中确认与取消窗口年龄）、面向与速度、受击/防御硬直计时、连段资格门（combo_active）、动作缓存（键/招式/正常与物理年龄/组合等待/锁定终点/投意图/按住集合）、方向历史（条目年龄化）与末位方向、落地与 jump 标记（prejump/落地恢复/just_landed/空中招式标记/额外恢复/跳向/跳跃槽/jump cancel 追击名单）、Hitstop 冻结与恢复边界。绝对帧号一律换算为相对年龄（纯调试帧号不入键，否则逐圈快照永不相等）；连段命中数/伤害/HP 等纯报告量不影响结算分支、不入键（combo_active 是取消与命中的资格门、入键）；动作键原始按压记录只在 ≤3 物理帧配对窗口内影响结算，等待候选与投意图经缓存字段入键；方向候选由历史+姿态在识别时确定派生，历史入键即覆盖；横向位置不入键——探针把木桩钉在玩家面向侧固定间距，横向几何是声明的探针假设（纵向位置/速度是真实结算量、入键）。`_run_schedule` 的逐圈快照改用该键（原 `_dummy_timing_state` 木桩时序键删除）。
- **循环上报语义**：`SolverCycle.Outcome` 枚举（PROVEN/BROKEN/HORIZON_TRUNCATED/LAPS_EXHAUSTED）承载分类，注记归类与汇总计数读枚举、不依赖措辞字符串。只有快照完全重现（PROVEN）的回边进入 `report.cycles`；帧数上限先于 8 圈对拍到达→「观测截断」注记（链条仍成立、已验证命中数如实报告，不用「断链」误述）；8 圈全部命中成立但快照未重现→「未完成观测」注记；两者都带「不宣称完整证明」。旧「观测上限内不断链保守上报为有效循环」行为废除，死字段 `sustained` 随之移除（与 proven 恒同值）。`report.incomplete_cycle_count` 供汇总声明「另有 N 个结构性循环观测截断/未完成」——safe 汇总不再以「未发现有效循环」掩盖未完成观测。
- **观测上限四处落地**：8 圈/2400 帧如上；240 帧恢复观测改为自命中帧起算（原实现按会话绝对帧计，长上下文里正常恢复会被误判截断——这是使「240 帧恢复观测」语义成立的修正），上限内未自然受身时 `recover_age` 按截断下限计并在边/缺口理由追加「截断下限而非实测恢复，不构成完整恢复观测」附注（`SolverEdge.recover_truncated`）；40 帧空中延迟按规格冻结值改为显式 `MAX_AIR_DELAY := 40`（≥ 玩家滞空 38 帧，超过滞空的延迟必然因落地作废，枚举完备、不会截掉可行延迟）。四上限及其语义写入 SCOPE_TEXT。
- **延迟搜索适配证明模式**：`_delay_dfs` 在循环证明模式（snapshot_every > 0）只有「快照重现」才提前返回——链条走完但未重现的向量不再终止搜索（另一组延迟可能完成证明）；路线模式保持首条完整成立即返回。失败代表性排序 `_run_ranks_higher` 让截断运行优先于断链运行（截断是更强的「未证明但未断」证据，避免把一组延迟下的截断误述为另一组的断链）。
- **循环报告材料与排序**：`SolverCycle` 新增 `start_text`（缺省/显式起始 + 入口招式真实键位起手）与 `inputs`（证明回放输入，截到重现对拍帧——回放到该帧恰好复现全部预期命中，测试回放验证命中数==按键数、入口键按压数==观测圈数）；循环小节打印路径/周期/证明结论/起始状态/输入计数，真实键位逐帧回放行进操作说明（`_replay_ops_text` 与路线回放共用同一口径）；solve() 对 cycles 按标签稳定排序；镜像签名扩展 start_text/inputs/laps。

# 角色招式实施规格（阶段 2）

Status: ready-for-agent

## Problem Statement

2026-09-23 的角色招式完整基线已经确定了普通链、被防取消、Rekka、236C ground slide、D 系真实位移与换边、空中出口、落地例外、j214D 弹地和跨状态修正。当前共享招式表仍是旧职责：缺少新招式资源、特殊受击状态、被防木桩入口、真实位移和起手分层修正；现有取消字段也不能区分命中确认、链式／必杀取消与恢复后的普通连接。

如果把这些规则分散到训练场、CombatSession 和 Combo Solver，各端会对同一条路线给出不同结果。尤其是被防被误当成命中、D 系先移动后判定、落地首帧被绕过、5D > 5B 被写成取消、或用静态钉位冒充真实换边，都会产生不可复现的连段结论。

## Solution

以现有 CombatSession 的确定性逐帧管线为运行时 seam，以 MoveTable 为共享资源和校验边界，以 HitProfile 为命中资料选择基础，分阶段交付角色招式的端到端可演示切片。每张票同时覆盖资源、战斗会话、训练场反馈、Solver 对应能力和正反例回放。

既有帧序继续有效：

1. 采样输入、更新方向和动作历史；
2. 生成本帧 D 系计划位移（不立即提交正式位置）；
3. 执行命中／被防判定；
4. 应用命中资料或独立被防结果；
5. 提交运动、碰撞、落地、触地和自然恢复；
6. 依据接触结果执行取消判定；
7. 在攻击者恢复且状态合法时消费普通连接缓存。

同一帧命中优先于落地。Hitstop 冻结动作、运动、状态计时、蓄力年龄和取消／缓存年龄，但继续采样输入。资源被修改时，训练场和 Solver 必须从同一份已校验表得到一致行为；非法表整表拒绝，不使用旧字段、数组顺序或 GameParams 回退。

## User Stories

1. 作为玩家，我想用 5A > 5B > 5C > 5D 完成稳定地面链，以便理解基础节奏。
2. 作为玩家，我想用 5B > 5D 走较短路线，以便在不同距离选择收尾。
3. 作为玩家，我想让 2A/2B 保留低位确认职责，以便站防与蹲防路线有区别。
4. 作为玩家，我想看到 2C 先造成低浮空再转普通倒地，以便扫倒不是隐式的普通命中。
5. 作为玩家，我想在命中或被防时使用链式／必杀取消，而挥空时不能取消，以便接触结果有明确意义。
6. 作为训练者，我想逐帧指定木桩站防、蹲防或空防，以便真实验证玩家攻击被防。
7. 作为玩家，我想在 214C 首段后选择 ~B 或 ~C，且第一次 B/C 输入就锁定分支，以便 Rekka 不依赖事后观察防守反应。
8. 作为玩家，我想让 214C~B/~C 按地面与空中资料产生不同结果，以便延长与收尾职责可区分。
9. 作为玩家，我想用 236C 的两段判定进入浮空／ground slide，并在命中当下特殊取消到普通 5D/5[D]。
10. 作为玩家，我想让特殊进入的 D 与普通 D 使用同一招式身份，D 命中后的 5B 只能在 D 恢复后作为普通连接成立。
11. 作为玩家，我想在中板用 5[D]，在版边用普通 5D，并观察实际位移、墙截断和换边。
12. 作为玩家，我想让 D 系 active 帧的扫掠参与命中，但被防或挥空不能穿到对手另一侧。
13. 作为玩家，我想用 6A 命中后 jump cancel，再用 jA/jB/jC 延续有限空中路线。
14. 作为玩家，我想让 6D/2D 只命中符合地空和高度条件的目标，并从命中结果进入已配置空中动作。
15. 作为玩家，我想区分 j5D 收束、j6D 普通落地连接与 j2D > 214C 专用落地例外。
16. 作为玩家，我想让最后一个空中物理帧先结算命中，再进入落地恢复；空中 active 不延续到落地恢复。
17. 作为玩家，我想让 j214D 对地面和空中目标统一进入 GROUND_BOUNCE，而不是伪装成 OTG 倒地。
18. 作为设计者，我想锁定首次有效命中的 A/B/C/D 起手等级，使修正跨 slide、Rekka、弹地和落地连接保留。
19. 作为设计者，我想让伤害、受击时间／连段窗口和轨迹各自累计与舍入，以便调校不会互相污染。
20. 作为设计者，我想让 A 起手可命中弹地但不能继续，B/C/D 起手只获得一次条件性继续，以便循环边界由状态资格表达。
21. 作为工具使用者，我想知道 Solver 证明的是 timing、静态空间还是实际回放，以便不把固定钉位结论误当成真实换边证明。
22. 作为测试者，我想通过同一份逐帧输入重放命中、被防、挥空、墙边、双面向和落地边界，以便问题可复现。
23. 作为玩家，我想看到当前招式、目标状态、命中／被防、修正和失败原因，以便训练场反馈能解释路线为何断开。

## Implementation Decisions

### 1. 共享数据与迁移

- MoveTable 继续是唯一已校验招式表；每招稳定 id、姿态、输入绑定、startup/active/recovery、优先级、取消窗口、属性、hitbox、基础伤害和至少一个合法命中资料都必须显式声明。
- 扩展 HitProfile/反应状态以表达 GROUND_SLIDE、LOW_FLOAT_SWEEP、LOW_FLOAT_TO_SLIDE、GROUND_BOUNCE 和空中向下击落资料。新增状态必须有独立计时、运动、触地／恢复事件和可追击域；不能把 slide 或 bounce 当作普通倒地 OTG。
- 命中资料仍按命中前目标状态 × 命中上下文精确匹配；缺失不回退，重复键或非法组合整表拒绝。GROUND_KNOCKDOWN 仍只接受 grounded 目标。
- 旧 hit_result、hitstun_frames、knockback、knockback_up、旧地面 214D 与单一 jD 职责必须迁移或移除；旧资源不通过兼容回退继续运行。236C 两段和 5[D] 必须能在资源中明确表示。
- 现有基础 CombatSession、MoveTable 和 HitProfile 能力只扩展缺口，不重做已验收的精确匹配、Hitstop、自然恢复和既有投／防御规则。

### 2. 输入、取消和普通连接

- 链式取消、必杀取消、命中确认取消是三种独立窗口。链式／必杀取消在命中或被防接触成立；命中确认、jump cancel、空中出口、来源资格和专用落地例外只在实际 HIT 成立；挥空没有接触和取消年龄。
- 5[D] 采用动作内蓄力：D 动作真正启动时开始计时，达到阈值自动提交蓄力版；启动前的按住、缓存和 Hitstop 不积攒。Hitstop 中不推进蓄力，阈值落在停顿内时在恢复首个正常帧触发。
- 214C 首段进入派生窗口后，第一次 B/C 新按下立即锁定 ~B/~C；派生状态优先于普通投的 B+C 组合等待，同帧 B+C 使用固定 C > B 优先级，之后另一键不能改写分支。
- 普通连接是独立于取消的恢复后目押：前招 recovery 期间可提前缓存，攻击者完全恢复后的首个合法帧才消费；目标仍须处于允许追击的状态且新招 active 真实重叠。普通连接不打断 recovery、不产生取消年龄、不借用来源资格或落地首帧例外。

### 3. 命中、被防和受击状态

- 木桩防御由逐帧显式 NONE/STAND/CROUCH/AIR 请求驱动，不引入 AI。请求不符合木桩当前状态时返回可观察失败原因，不回退为其他防御。
- 被防是独立接触结果，至少记录 BLOCKED、防御姿态、被防停顿、被防硬直和被防推退。其数值不读取命中资料；命中、被防、挥空三分支在事件和取消资格中可区分。
- 被防可开放配置的链式／必杀取消，但不开放 jump cancel、专用击飞、空中出口、236C → 5D/5[D] 来源资格或命中确认取消。安全性只能通过固定反击招式、时机、距离、版中／版边和面向的真实场景报告，不能由硬直字段单独推断。
- 236C 两段分别结算：第一段被防立即终止，第一段挥空不追踪但继续第二段；两段实际命中都可取得 D 特殊取消资格。第二段命中 grounded 目标进入浮空并在触地时进入 slide；命中 airborne 使用独立空中资料；slide 目标无显式 profile 时无命中。
- 2C 进入短暂低浮空并在触地转换为普通倒地；普通 5D 因 startup／剩余硬直失败，2D 因高度不匹配失败，214C~B 路线可成立。
- 214C~B grounded 命中进入普通倒地、airborne 命中短暂延长浮空；214C~C grounded 命中直接倒地，airborne 使用独立向下击落资料。派生被防只产生对应被防结果。
- j2D 只有实际命中取得一次 J2D_LANDING_214C 资格；Hitstop 中可缓存 214C，落地首帧仍不可行动，首个可行动帧消费并清除资格。j6D 和其他空技只走普通落地恢复与普通连接。
- j214D 对 grounded/airborne 目标都进入 GROUND_BOUNCE；第一次触地才开放统一追击窗口，不刷新空中资源，不转普通倒地且最多一次反弹。A 起手的 bounce followup 为 0；B/C/D 起手为一次性 1，成功追击后消费。

### 4. D 系位移和换边

- D 系当前帧先生成计划位移，命中判定读取计划后的攻击姿态，运动阶段再提交经版边和身体碰撞约束后的正式位置；不能先移动再重跑命中阶段。
- active 帧使用起点到计划姿态的确定性扫掠覆盖；startup/recovery 不参与扫掠。实际命中才开放本次位移对目标的身体穿越；被防、挥空、缺失资料或墙截断停在原侧。
- 只有实际命中且实际终点跨过目标才记录换边。命中当帧先完成攻击与位移，下一帧依据真实横向关系更新面向；已开始的 214/236 方向候选锁定首次相对面向，不因换边重解释。
- 5D/5[D] 共用换边规则；5[D] 的轨迹更远且提交更慢。6D 继承相同穿越口径，j5D/j6D/j2D 的空中运动按各自资料处理。

### 5. 起手与三层修正

- 首次实际 HIT 锁定招式声明的 starter grade A/B/C/D；被防和挥空不锁定，后续状态转换不提升或重置。
- 每次有效命中分别累计 damage_scale、time_scale、trajectory_scale。先乘 starter 倍率，再乘本招／状态倍率；每层独立舍入，伤害保留 10% 底线，时间和轨迹不套伤害底线。自然恢复、普通倒地、落地结束或连段结束清除。
- 状态局部资格负责有限继续：A 起手不能继续弹地后的路线或形成禁止的 slide loop；B/C/D 只允许在剩余硬直、空间和显式边满足时一次性继续。禁止用全局命中数或总时长上限掩盖循环。

### 6. Solver 与真实空间回放

- Solver 与运行时读取同一份校验后的 MoveTable 和命中资料选择器；报告必须区分 timing-valid、可选 spatial-valid、replay-required、configuration-gap、state-incompatible、distance-insufficient、wall-clamped、buffer-expired 与 not-supported。
- Solver 支持地面／空中、normal／counter、普通硬直、浮空、普通倒地、slide、低浮空、Rekka 派生、bounce、落地例外、起手等级、三层修正和一次性来源／追击资格的状态追踪；只要某个状态尚未交付，就必须明确报告未支持，不能用静态可达性代替。
- 状态键至少包含玩家／目标姿态和状态、招式与帧、面向、速度和垂直位置、受击／防御计时、输入缓存与方向历史、起手等级、三层累计修正、slide/bounce/落地／来源资格、反弹次数、实际命中次数和影响未来行为的位置关系。纯报告计数不进入键。
- 现有 Solver 的静态空间检查只表示给定站位、碰撞盒、hitbox、垂直轨迹和面向下的结果；不搜索走位、中立、墙角、推挤、跨身或屏幕边界。真实 D 系位移、击退、身体碰撞、墙截断、换边和镜像必须由保留实际位置的训练场回放证明。
- 空间验收按中板／版边、近／远距离、左右面向、命中／被防／挥空、墙截断、目标地面／空中和输入提前量组织；静态钉位证据与真实回放证据分开记录。

### 7. 训练场反馈和资源迁移完成定义

训练场至少显示当前招式与阶段、目标状态、命中／被防／挥空、当前修正和失败原因；失败原因不能只写“连段断开”。每条代表路线都要有逐帧输入、起点、面向、距离、事件日志和结果。

阶段 2 只发布本规格和票据，不实现战斗代码、数值最终平衡、美术／音效或完整动画。

### 9. 字段、状态和顺序校验

- 核心字段缺失使用未声明哨兵并拒绝；不得把未声明计时、速度、属性、输入或 starter grade 解释为 0、旧值或动作键推断。
- HitProfile 的唯一键是 target_state × hit_context；reaction、适用状态、计时和速度组合必须合法。Counter 资料必须与同状态 normal 成对；未知状态、重复键、负数有效值和旧字段残留整表拒绝。
- 新状态至少要声明进入来源、计时、水平／垂直运动、触地或恢复事件、可追击域、修正继承／清除规则和 Solver 状态键字段。状态标签不能绕过精确 profile 选择。
- 同帧顺序固定为输入 → 计划位移 → 命中／被防 → 受击应用 → 运动／落地／触地／自然恢复 → 取消 → 缓存消费；命中先于落地。普通连接消费不打断 recovery，j2D 例外不跳过落地首帧锁。
- manifest 迁移后必须只引用新稳定 id；旧 214D、jD、hit_result、hitstun_frames、knockback 和 knockback_up 不得继续作为运行时或 Solver 的隐式输入。

### 10. 阶段 3–9 路线矩阵

## Testing Decisions

- 以确定性 CombatSession 逐帧输入验证外部事件、状态、位置和时间；不依赖私有函数或渲染像素。
- 以同一 manifest 驱动运行时和 Solver，测试合法资源同步变化、非法资源整表拒绝和错误原因一致。
- 旧 HitProfile 选择、Hitstop、自然恢复、普通倒地、输入缓存、方向候选和既有防御／投规则必须回归；不重写已交付测试。
- 每个实施切片至少有一条成功路线、一条同条件失败路线和一条接触分支（命中／被防／挥空或地面／空中）。阶段 5 起必须再有真实空间回放或明确的 replay-required 阻断。
- 状态测试覆盖 slide、低浮空转倒地、Rekka 地空差异、bounce 触地／反弹、j2D 落地首帧、被防独立计时和状态结束事件。
- 修正测试覆盖 A/B/C/D 首击、每层累计与舍入、跨状态保留、A 禁止路线、B+ 一次性继续和资格清除；不以全局命中数或时间上限代替。
- Solver 测试覆盖普通连接与取消的分类、配置缺口、时序有效但距离不足、有限资源、状态键去重和真实回放边界。静态空间结果不得升级为真实空间结论。
- 人工判断集中在：扫掠细分和边界容差、实际穿越／墙边手感、被防反击安全性、2C 低浮空节拍、j2D 落地节拍、bounce 追击节拍、A/B loop 手感与最终参数。自动化通过不等于真人验收通过。

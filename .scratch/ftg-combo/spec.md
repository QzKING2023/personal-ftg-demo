# FTG Demo 连段系统实现规格

Status: ready-for-agent

## Problem Statement

FTG Demo 当前只有单一基础招式和简单受击反馈，无法验证项目已经确定的短流程展示：玩家需要通过 A/B/C/D、方向序列和 Space 操作一名玩家角色，稳定地跑通地面路线和浮空/空中路线，并观察木桩的命中、受击、自然受身和恢复过程。

如果输入缓存、命中确认取消、落地处理、自然受身和伤害递减分别由不同逻辑自行判断，连段结果会依赖处理顺序，容易出现挥空取消、落地绕过取消、受身后继续追击或招式循环无法发现的问题。

## Solution

增加一个轻量的、确定性的战斗会话作为运行时战斗 seam。战斗会话按物理帧接收输入并结算玩家角色与木桩的状态，输出可供训练场反馈使用的状态快照和战斗事件。招式数据描述窗口、伤害、受击结果、取消条件、路线接续和姿态要求；运行状态保存输入缓存、连段命中数、伤害倍率、玩家状态和木桩状态。

每个物理帧严格按以下顺序结算：

1. 记录输入并更新输入历史。
2. 执行命中判定。
3. 应用受击结果和连段伤害。
4. 更新运动、落地和自然受身。
5. 根据命中确认和当前姿态判断取消。
6. 消费合资格的缓存输入。

同一物理帧同时发生命中和落地时，命中先刷新受击硬直，再处理落地，最后判断取消。`Combo Solver` 使用同一份招式数据作为开发期工具，生成确定性接续图并检测有效循环；它不进入运行时战斗流程。

## User Stories

1. 作为玩家，我想用 A/B/C/D 分别触发有明确语义的招式，以便理解每个动作键在连段中的作用。
2. 作为玩家，我想用方向序列触发 236C 和 214D 等派生招式，以便执行有方向要求的连段路线。
3. 作为玩家，我想在招式取消窗口前后输入下一个动作，以便通过短暂输入缓存稳定完成连段。
4. 作为玩家，我希望动作键输入最多缓存 6 个物理帧，并由最新输入覆盖旧输入，以便输入窗口有容错但不会积累不可控的旧指令。
5. 作为玩家，我希望方向序列拥有独立的输入历史窗口，以便方向识别不受动作键缓存长度限制。
6. 作为玩家，我希望挥空不会获得命中确认取消资格，以便只有有效命中才能继续主路线。
7. 作为玩家，我希望能跑通“地面起手 → 地面连接 → 地面收尾”的稳定路线，以便快速验证基础招式节奏。
8. 作为玩家，我希望能跑通“地面起手 → 浮空 → 浮空追击 → 空中路线 → 空中收尾”的进阶路线，以便验证特殊追击窗口。
9. 作为玩家，我希望只有招式明确配置且已经命中确认时，Space 才能执行 jump cancel，以便未配置的跳跃不会意外延长连段。
10. 作为玩家，我希望 jump cancel 后从指定的空中起手招式开始，并且不能通过二段跳或重复刷新滞空资源无限追击。
11. 作为玩家，我希望同一帧的命中优先于落地，以便临界帧命中仍能正确刷新木桩受击状态。
12. 作为玩家，我希望木桩在地面受击、浮空受击、空中已受身和倒地处理中表现出明确状态，以便理解当前能否继续追击。
13. 作为玩家，我希望木桩自然受身或恢复时连段结束，浮空受身后先落地再恢复中立，以便连段终止来自受击状态而不是隐藏的全局计时器。
14. 作为玩家，我希望连段伤害随命中数递减但最低保留 10%，以便长连段仍有反馈而不会造成数值归零。
15. 作为设计者，我希望训练场显示连段命中数和木桩当前状态，以便调整招式帧数和取消窗口。
16. 作为设计者，我希望可以在不修改运行时战斗逻辑的情况下调整招式数据，以便试验前摇、后摇、硬直、取消窗口和路线接续。
17. 作为设计者，我希望 `Combo Solver` 能发现有效招式循环，并排除等待超时、姿态不符或有限空中资源无法续期的伪循环，以便在加入新招式时避免无限路线。
18. 作为测试者，我希望可以通过逐帧输入和可见状态快照复现边界情况，以便验证输入、命中、受击、运动、取消和缓存消费的顺序。
19. 作为玩家，我希望重置训练场后玩家、木桩、连段命中数和受击状态全部恢复初始值，以便重复练习。

## Implementation Decisions

- 运行时采用轻量状态机、招式数据和集中战斗结算，不引入 ECS。
- 运行时最高测试 seam 是确定性的战斗会话逐帧结算；训练场只负责输入适配、场景呈现、状态反馈和重置。
- 玩家状态至少区分地面/空中、中立/执行招式/命中确认/后摇/落地；木桩状态至少区分中立、地面受击硬直、浮空受击、空中已受身和倒地处理。
- 招式数据描述 startup、active、recovery、基础伤害、受击结果、取消窗口、取消目标、姿态要求、方向派生和 jump cancel 配置。
- 动作键采用单槽缓存，年龄 0–5 有效，年龄 6 先过期；最新动作覆盖旧动作；只在命中确认取消阶段消费；Space 不进入该缓存。
- 方向输入使用独立的默认 24 帧历史窗口，年龄 0–23 有效；识别 236C 或 214D 后消费方向序列并锁定派生招式。
- 主路线只允许命中确认取消；没有合法取消资格的独立招式不能绕过取消条件追击仍在受击中的木桩。
- 稳定路线固定为“地面起手 → 地面连接 → 地面收尾”。进阶路线固定为“地面起手 → 浮空 → 浮空追击 → 空中路线 → 空中收尾”。收尾表示路线终点，不主动清除木桩倒地处理或强制让木桩立即恢复。
- 当前招式语义采用：A 为地面起手和空中追击，B 为地面/空中连接，C 为地面浮空，D 为收尾；236C 和 214D 为方向派生；空中 C 暂不配置。
- jump cancel 必须同时满足招式配置和命中确认；默认从 jA 开始空中追击；jB 的 D → 5D 只在显式落地接续条件下成立；不允许二段跳。
- 玩家跳跃默认持续 40 个物理帧，木桩浮空默认给予 48 个物理帧滞空；后续追击不刷新滞空资源；落地保留剩余受击硬直。
- 连段伤害倍率采用 `max(0.1, 1 - (命中数 - 1) × 0.1)`；不设置全局最大命中数或连段总时长上限。
- 木桩地面硬直归零时自然受身并断连；浮空受身先结束连段，落地后恢复中立；受身和连段收尾是独立判定。
- `Combo Solver` 只读取招式数据，检查前摇、取消等待、取消窗口、受击硬直、地面/空中姿态、jump cancel 和落地接缝；必须报告有效循环，不能用全局最大命中数掩盖循环。
- 招式帧数和输入窗口应保持可调。原型中尚未完成真人键盘确认的 6 帧缓存、0–8 帧取消窗口、24 帧方向窗口、jump cancel 节奏和受身/落地视觉间隔，作为首轮实现的可调参数和验收风险保留。
- 训练反馈至少显示连段命中数和木桩当前状态；不额外增加断连提示，不加入 AI 或胜负回合。

## Testing Decisions

- 运行时测试通过确定性的战斗会话 seam 驱动输入帧序列，只验证外部可观察状态和事件，不依赖节点私有实现细节。
- 测试必须覆盖动作键缓存的年龄边界、最新输入覆盖、挥空不消费、方向历史独立过期、方向序列消费和派生锁定。
- 测试必须覆盖地面路线、浮空路线、jump cancel 的配置限制、空中不可二段跳，以及没有合法取消时不能绕过取消继续追击。
- 测试必须覆盖同帧命中和落地的顺序，确认命中先刷新硬直、落地随后处理、最后才判断取消和消费缓存。
- 测试必须覆盖地面自然受身、浮空受身、落地恢复中立、收尾保留倒地处理，以及连段命中数在受身后停止增长。
- 测试必须覆盖伤害倍率的前三击递减、10% 下限和没有人为命中数上限。
- `Combo Solver` 测试通过其独立 seam 验证：正常地面/空中路线可达、有效回边被报告为循环、超时回边和姿态不符回边被排除、有限空中资源不能被误报为可无限续期。
- 训练场集成测试验证输入适配、状态反馈、重置和基础碰撞仍然可用；逻辑测试不依赖渲染结果。
- 人工试玩用于确认参数手感：6 帧缓存、0–8 帧取消窗口、24 帧方向窗口、jump cancel 后 jA 的节奏，以及受身/落地之间的视觉间隔。试玩结果可以调整招式参数，但不能绕过已确定的结算顺序和状态边界。

## Out of Scope

- 多角色、多目标或复杂并行战斗。
- 木桩 AI、防御、闪避、蹲下和胜负回合。
- OTG、地面弹跳、墙反弹、二段跳和未配置的空中 C。
- 全局最大命中数、全局连段总时长或额外的硬直最低值。
- ECS、复杂动画系统、角色美术资产、音效、屏幕震动、联网和手柄适配。
- 将 `Combo Solver` 做成运行时战斗系统。
- 由任意空间碰撞、自由中立或未经招式数据配置的普通连接自动推断连段。

## Further Notes

原型逻辑验证没有发现规则失败，但真人键盘手感尚未完成确认。因此首轮实现应保留这些参数的调节能力，并把试玩结果记录为实现后的参数决策。实现必须继续遵守已接受的“轻量战斗状态与集中结算”和“以自然受击恢复结束连段”两项架构决策。

规格完成后，下一步是使用 `to-tickets` 将工作拆成带阻塞关系的垂直切片；票据应优先覆盖可运行的逐帧战斗会话，再接入招式数据、两条路线、训练反馈和 Solver 验证。

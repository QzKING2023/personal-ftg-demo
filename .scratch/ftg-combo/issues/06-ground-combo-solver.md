# 06: Solver 地面接续验证与循环报告

**What to build:** 设计者可以用开发期 Combo Solver 检查基础地面路线的合法接续和有效循环，并得到可读的验证结果，而不改变运行时战斗。方向派生和空中接续由 07 覆盖。

**Blocked by:** 02: 稳定地面路线与输入缓存.

**Status:** ready-for-human

- [x] Solver 使用与运行时一致的招式数据，生成 5A/5B/5D 基础地面招式的确定性接续图和可读路径。
- [x] 接续检查考虑前摇、等待时间、取消窗口、木桩硬直和地面姿态。
- [x] 有效的地面回边会被报告为循环；等待超时、取消窗口不满足或姿态不符的回边不会被误报。
- [x] Solver 运行不会修改运行时战斗状态，也不会通过全局最大命中数或总时长限制掩盖循环。
- [x] 测试包含正常 `5A → 5B → 5D` 路线、注入的有效回边和无效回边，并验证报告内容。

## Comments

**2026-09-13 实现完成（agent）：**

- 新增 `scripts/combat/combo_solver.gd`（`ComboSolver.analyze(招式表)`）：开发期工具，不改运行时战斗。核心口径是不在 Solver 里复刻第二套帧物理——每条接续边、每条路线、每个循环都由**一次性私有 CombatSession 探针**在真实结算中验证（探针把木桩钉在命中范围内：几何接触是假设不是证明，报告的 scope 行明确声明）。
- 接续图：节点为可用普通动作键（5X）起手、无方向派生的地面招式；边来自 `cancel_targets`。排除原因分类：目标不存在 / 姿态不符（空中目标）/ 方向派生（07）/ 浮空命中的后续（07）/ 收尾招式不开放取消 / 等待超时（最早命中晚于木桩恢复，连段重新计数）/ 取消未成立。每条有效边报告等待范围 `[0, min(取消窗口, 木桩恢复 − 目标前摇)]`——取消须在窗口内且目标命中（等待 + 前摇）不晚于木桩恢复，窗口与硬直共同收窄（硬直 4 的 5F 接前摇 4 的 5B 只有 w=0 可用；窗口 2 的 5G 被窗口收窄到 0–2）、最早命中年龄与恢复年龄（5A/5B：恢复第 21 帧 = 滞空 10 + 硬直 12 − 1，与运行时对拍一致）。
- 可读路线：有效边上的极大简单路径逐条模拟（每次取消都在命中确认当帧消费），报告命中帧/连段数/递减总伤害；默认表 `5A → 5B → 5D` 命中帧 6/10/15、3 hit、伤害 35.2，与 `_test_ground_route` 的运行时结果完全一致。
- 循环判定：有效边上的初等回路（按字典序旋转去重）逐圈模拟，每圈回到起点命中时快照木桩时序状态（状态/剩余硬直/垂直速度与高度/是否落地）；**快照完全重现即证明可无限重复**，不设全局命中数或总时长上限。注入 `5B → 5A` 回边后报告周期 27 帧、第 4 圈起点状态重现。观测上限（8 圈/2400 帧）内不断链的回边保守上报为循环（宁可误报不可掩盖）；图上有回路但逐圈断链的情况记入 notes，不算循环。
- 边界语义与运行时一致：命中判定先于当帧恢复结算——硬直 4 的 5F（无击飞）取消进前摇 4 的 5B，最早命中恰落在恢复帧当帧仍有效；前摇 5 的 5A 则等待超时被排除。当前 MoveData 语义下「仅取消窗口不满足」不可达（最早取消 w=0 恰为命中帧、窗口恒开放），窗口作为有效等待范围的上界参与检验。
- 隔离性：所有探针使用私有会话，测试断言运行中的会话在 Solver 分析前后可观察状态逐字段不变。
- 测试：`tests/test_combo_solver.gd` 52 项（默认表报告内容、与运行时对拍、注入有效回边检出循环、等待超时/姿态不符/收尾回边不误报、窗口与硬直分别收窄有效等待、运行时状态不被修改、报告文本、确定性）；运行时打印默认表可读报告。session 277 + smoke 63 全部通过，无回归。

## 待定决策

### A1：首版角色主要奖励哪种体验？（已接受）

已接受：以「浮空追击与空中连段」为主。玩家先掌握把对手送入浮空的地面入口，再学习 jump cancel 后的空中追击；地面短路线服务于进入浮空，不成为与空中路线平行的第二主体验。指令操作是否提供更高回报，留到逐招职责决定。

理由：已有短流程展示目标及两套路线骨架，能够在保留现有计时、落地和自然受身约束的前提下，优先解决每招为什么使用的问题。

本轮已接受的边界：

- 地面招式的首要价值是把对手送入可追击的浮空状态，并为 jump cancel 提供清楚的确认点。
- 空中路线的终点仍是 jD；不因选择空中主体验而加入二段跳、high-jump 或自动延长空中资源。
- 地面短路线可以存在，但它的设计评价要看是否帮助进入浮空、是否提供不选择浮空时的明确收尾，而不是追求独立的长地面连段。

具体边界：

- 允许的候选体验：5A 命中后走 5B → 5D；近距离且输入/时机合适时选择 236C → jump cancel → jA → jB → jD。两者来自当前路线，不代表首版路线已定。
- 拒绝的继承边界：5A 挥空也启动相同取消链；jB 落地首帧直接转 5D；木桩已自然受身后仍把下一击计入原连段。
- 历史空间证据：地面样本 70px 成立，完整空中样本 48px 成立而 70px 失败。不能承诺所有 5A 命中距离都能走完整空中路线；是否扩大容错是后续设计问题。

这只确定体验优先级，不自动接受用途表、最终路线、距离容错或新效果。

### A2：是否新增专用浮空入口？（已接受）

用户提出：需要新的「进入浮空状态」或「击飞」类招式，认为 5C 作为击飞招式较少见，候选包括 6A 击飞或 2C 扫倒（落地前保持某种浮空状态）。

术语核对：当前**浮空受击**是已有 `LAUNCH` 命中结果，表示木桩进入空中受击硬直；**击飞招式**暂作为“地面招式命中后把目标送入浮空受击、并可成为 jump cancel 入口”的候选称呼。**扫倒**、**倒地**、**地面弹起**和“落地前浮空”不是当前已定义状态，不能把它们当成`LAUNCH` 的同义词。

推荐：接受新增一个专用击飞入口，优先采用 6A 类地面特殊技；保留现有 5C/236C 的后续定位讨论，但不再强迫 5C 承担专用击飞职责。2C 扫倒及其落地前状态延期，除非项目明确愿意新增倒地、受身、落地前状态及相应 Solver 语义。

允许/拒绝边界：

- 允许：新增 6A 类招式，命中结果沿用现有浮空受击语义，并在命中确认窗口内 jump cancel 到空中入口。
- 允许：5C 或 236C 改成非专用的高回报打击、地面连接或其他职责；具体用途留到下一轮逐招定位。
- 允许：以后单独设计 2C 扫倒，但必须先定义它与浮空受击、倒地、受身和落地恢复的关系。
- 拒绝：仅改名或复制 5C/236C 就声称新增了独立击飞职责。
- 拒绝：挥空的新增击飞招式自动获得 jump cancel；或让其绕过命中确认、可追击和现有取消窗口。
- 拒绝：为凸显空中主体验，新增未讨论的二段跳、空中自动续期、落地首帧取消或改变自然受身。

已接受：新增一个 6A 类专用击飞入口；2C 扫倒及其落地前状态延期。6A 的具体输入、取消边和帧数仍待定。

### A3：6A 的输入与使用位置（已接受）

推荐：6A 是地面可自由行动时可直接输入的前方向特殊技，使用 `6+A` 的显式方向输入；它也可以成为命中确认取消目标，但不能只允许从某个前置招式派生。这样玩家能清楚练习“直接击飞”，也能把地面确认接入空中主路线。它不在空中、pre-jump、受击/防御硬直或落地恢复中独立起手。

允许/拒绝边界：

- 允许：地面中立输入 6A，命中后进入现有浮空受击；在开放的命中确认窗口内 jump cancel 到空中入口。
- 允许：已有地面招式在命中确认后把 6A 列为显式取消目标，形成“地面确认 → 专用击飞 → 空中追击”。
- 拒绝：把 6A 设计成无方向的 A 变体，导致普通 5A 与击飞入口无法区分。
- 拒绝：6A 只能从一条隐藏派生进入，玩家无法从地面中立练习或识别其用途。
- 拒绝：6A 在挥空、被防或木桩已自然受身后取得 jump cancel；或在 pre-jump、空中、落地恢复期间绕过现有状态门。

已接受：6A 是地面自由行动时可直接输入的 `6+A` 前方向特殊技，也可作为命中确认取消目标；具体哪些招式开放该取消边、6A 的帧数和回报仍待定。

### A4：哪些地面招式可取消到 6A？（已接受，按用户意见修订）

用户修订并接受：6A 是首版唯一专用击飞入口；5C 改为普通地面连击招式，并允许 `5C → 6A`；236C 不再承担击飞，后续重新设计必杀技。5D/214D 的收尾职责暂不因本项自动改变。

当前接受的地面进入边候选为 `5A → 6A`、`5B → 6A`、`5C → 6A`；它们都仍需实际命中、窗口开放、姿态合法和木桩可追击。最终帧数与真实距离另在 D 轮验收，不在本轮纸面保证。

允许/拒绝边界：

- 允许：新增 6A 沿用现有浮空受击语义，并在命中确认窗口内 jump cancel 到空中入口。
- 允许：5C 作为普通地面连击招式接到 6A；236C 暂退出首版击飞职责，后续作为必杀技重新设计。
- 允许：地面中立直接 6A，不依赖前置招式；取消资格仍需实际命中、窗口开放和木桩可追击。
- 拒绝：5D/214D 收尾后再取消到 6A，形成无条件收尾回边。
- 拒绝：把 236C 继续当作首版专用击飞入口，或让 5C 保留与 6A 重叠的浮空职责。

已接受：首版允许 `5A → 6A`、`5B → 6A`、`5C → 6A`；5C 是普通地面连击招式，236C 的必杀技职责延期重设计。

### A5：5C 的地面连击出口（按用户意见重开）

用户拒绝“5C 只通向 6A”的过窄职责，提出允许取消到必杀技或连接到 D 系，并参考 BlazBlue 的 A→B→C→D Revolver Action/Gatling。

外部机制核对（用于辨认缺口，不直接作为本项目规则）：

- BlazBlue 的资料把普通攻击之间的链式取消称为 Revolver Action；一般流程是 A → B → C → D，但具体表由角色决定，存在例外。普通攻击还通常可以取消到必杀技；这些是与普通攻击链分开的取消类别。[BBCF System Mechanics](https://mail.dustloop.com/w/BBCF/Mechanics)、[BlazBlue notation guide](https://www.dustloop.com/guides/bbcs/systemGuide/notation.html)
- 资料明确区分“取消许可”和“实际连段”：取消可能在命中或防御成立，少数规则甚至允许挥空；合法取消不保证下一招实际命中。[BBCF System Mechanics](https://mail.dustloop.com/w/BBCF/Mechanics)

与当前项目的差距：

1. 当前 `cancel_targets` 只表达命中确认路线；没有独立的普通攻击链/必杀取消类别。
2. 当前取消阶段要求实际命中确认和木桩可追击；还没有“被防可取消”资格，防御硬直关系本身仍待 C 轮决定。
3. 当前资源有 `command_tier`，但没有普通拳脚、指令普通技、必杀技的完整职责分类；`6A` 的分类也尚未固化。
4. 当前窗口以命中确认后的正常帧年龄表达；BB-like 链式取消还需要明确是恢复打断窗口、命中/防御/挥空资格、输入缓存和同键重复规则。
5. Solver 目前把显式目标列表当作运行时硬约束；若改成类别规则加例外，Solver、非法数据校验和报告必须共享同一张有效边表。

推荐：引入两层规则，但暂不接受完整 BB-like 行为为既定事实：

- **链式取消候选**：普通地面招式之间的显式或类别化边，例如 `5A → 5B → 5C → 5D`，以及`5C → 6A`；其资格可另行决定为命中/被防/挥空中的一部分。
- **必杀取消候选**：普通招式进入后续必杀技，例如未来重设计后的 `5C → 236C`；这不等于 5C 恢复了击飞职责。
- **命中确认取消**：继续保留给 jump cancel、6A 后空中路线和需要木桩可追击的特殊路线。

允许/拒绝边界：

- 允许：`5A → 5B → 5C → 5D` 作为普通地面链，或`5C → 6A → jump cancel` 作为浮空入口；具体边仍需角色表确认。
- 允许：未来 `5C → 必杀技`，只要必杀技的新职责、资格和命中结果另行确定。
- 拒绝：用一个布尔 `can_cancel` 同时表示普通链、必杀取消、jump cancel 和命中确认路线。
- 拒绝：因为“BB-like”就自动开放所有 A/B/C/D 互相取消，或把被防、挥空和命中视为同一资格。
- 拒绝：把 5C→D 的合法取消误报为必然连段；距离、硬直、击退和自然受身仍单独验证。

### A6：是否引入独立的 BB-like 链式取消层？（已接受）

推荐：接受“链式取消”和“必杀取消”作为独立于命中确认取消的规则层；首版先用显式逐招边表达，暂不引入全局 A→B→C→D 自动推导。这样能让 5C 拥有足够职责，同时保留角色例外、被防资格和 Solver 可验证性。

已接受：引入独立的**链式取消**和**必杀取消**规则层；首版使用逐招显式边，不自动推导全局 A→B→C→D。命中确认取消继续服务于 jump cancel、6A 后空中路线和要求木桩可追击的特殊路线。

### B1：链式/必杀取消的成立资格（已接受）

推荐：首版让链式取消和必杀取消在**命中或被防**时成立；挥空不成立。这样保留 BB-like 的“攻击接触后可继续压制/连段”体验，又不把挥空取消做成额外移动工具。jump cancel 和专用击飞路线仍沿用命中确认资格，不因新层自动放宽。

这会要求后续 C 轮明确独立的防御硬直语义；当前代码复用 `hitstun_frames` 只是缺口，不能假装已完成。

允许/拒绝边界：

- 允许：5A 命中后链到 5B；5A 被防后仍可按规则链到 5B，但后续是否形成连段另判。
- 允许：5C 命中或被防后进入未来必杀技；具体必杀技职责另行设计。
- 拒绝：5A 挥空后链到 5B，借链式取消延长攻击覆盖或移动。
- 拒绝：被防的 5A 因没有独立防御硬直定义而直接当作命中确认，获得 6A jump cancel。
- 拒绝：新层绕过落地恢复、pre-jump、空中姿态或自然受身基线。

## C1：目标状态资料匹配（已接受）

`grounded` 与`airborne` 是独立的目标状态维度。招式只对显式声明了`HitProfile` 的目标状态匹配；缺失状态不命中，不回退到另一状态的资料。这样同一招若要同时处理地面与空中目标，必须分别声明两份结果，速度、硬直与受身资料不会从地面值推导。

## C2：普通命中与浮空运动（已接受）

- `grounded + normal` 保持目标接地，应用 profile 的水平速度，垂直速度为 0。
- 只有 `launch` 反应可以给地面目标垂直初速度并转入浮空受击。
- `airborne` 命中由空中 profile 明确给出水平/垂直速度与空中受身计时，不继承地面 profile。
- 旧的单一 `knockback_up` 语义不能继续让普通`GROUND_HITSTUN` 隐式离地；迁移时必须由 reaction/profile 明确表达。

## C3：硬直、空中受身与普通倒地计时（已接受）

- 地面硬直只在目标接地时递减，归零当帧进入中立并产生自然恢复事件。
- 空中受身计时只在目标离地时递减；归零时进入空中已受身，连段立即结束，落地后回到中立。
- 空中目标在计时归零前落地时，转为地面硬直并沿用剩余帧继续递减。
- 普通倒地有独立倒地计时；命中即结束连段，计时结束才恢复，不接受主动受身。

## C4：倒地追击边界（已接受）

`GROUND_KNOCKDOWN` 期间木桩不接受任何打击，命中不刷新倒地计时，也不开启新连段。倒地计时结束产生恢复事件并回到`NEUTRAL` 后，下一次命中才可开启新连段。OTG 未来若加入，必须使用单独的`downed/otg` 目标状态和追击资格，不能由普通`grounded` profile 覆盖。

## C5：Counter Hit 触发、消耗与结束（已接受）

- 触发条件是攻击命中目标的显式反击易受击窗口；首版木桩的招式 startup 与 recovery 属于该窗口，active 不属于。
- Counter Hit 只作用于当前命中：按 `target_state × counter` 选择一次 profile，可改变伤害、硬直、速度或反应，但不产生持续 buff。
- 命中结果应用完即清除反击上下文；窗口结束前未命中则机会消失，下一次命中按 normal 处理。
- Counter Hit 可以与 `grounded`/`airborne` 组合，但不改变倒地不可追击、浮空受身或普通倒地的状态规则。

## C6：数据分层（已接受）

`MoveData` 持有招式身份、输入/姿态、startup/active/recovery、攻击属性与命中框、取消规则及公共伤害；命中结果改由内嵌的类型化`HitProfile[]` 承载。每个 profile 以`target_state × hit_context` 为唯一键，包含反应、运动和对应计时。首版不拆独立 profile`.tres` 文件，不使用通用字符串标签或平行的`ground_*`/`air_*`/`counter_*` 字段。

## C7：计时与运动字段（已接受）

- `ground_stun_frames`、`air_untech_frames`、`knockdown_frames` 单位均为正常物理帧，默认`-1` 表示未声明；按 reaction 恰好一个有效。
- `horizontal_speed_px_s` 与`upward_speed_px_s` 单位为 px/s，都是非负幅值；水平速度沿攻击者面向施加。`normal`/倒地向上速度为 0，`launch` 向上速度大于 0。
- `MoveData.base_damage` 是必填的非负整数；`HitProfile.damage_override` 默认`-1`，仅在需要差异时以非负整数覆盖公共伤害。
- Hitstop 继续沿用现有全局停顿规则，首版不由 profile 覆盖；停顿不消耗上述任何计时。

## C8：匹配优先级与非法组合（已接受）

运行时按 `target_state` 再按`hit_context` 精确匹配；任一维度缺失即不命中，不回退。重复键、未知枚举、负数、计时与 reaction 不一致、只声明 Counter Hit 而没有同目标状态 normal profile，及本轮未支持的`downed/otg`、bounce、wallbounce、invulnerability 都由`MoveTable` 整表拒绝。

反应约束：`GROUND_HITSTUN` 仅适用于 grounded 并使用地面硬直；`LAUNCH` 适用于 grounded/airborne 并使用空中受身；`GROUND_KNOCKDOWN` 仅适用于 grounded 并使用独立倒地计时。普通地面命中不得隐式离地。

## C9：可验收样例（已接受，数值待 D 轮）

本轮样例冻结字段、状态、匹配和相对差异，不冻结最终帧数、速度或伤害数值：

| 样例 | 必需 profile/前置 | 验收断言 |
| --- | --- | --- |
| 普通地面技（以 5A 为样例） | `grounded × normal` 与`grounded × counter`；可不声明 airborne | 普通命中保持接地并进入地面硬直；反击窗口命中选择 counter profile；空中目标没有 profile 时不命中 |
| 6A 击飞 | `grounded × normal/counter` 的`LAUNCH`；若允许打空中目标，再声明`airborne × normal/counter` | 地面命中获得向上速度并进入浮空受击；空中命中使用自己的速度/受身资料；命中确认后可进入已配置的 jump cancel |
| 214D 倒地 | `grounded × normal/counter` 的`GROUND_KNOCKDOWN` | 命中立即结束连段并进入独立倒地；倒地计时结束才恢复；倒地期间任何打击都不命中 |
| Counter Hit | 木桩在 startup 或 recovery，且命中对应 target_state 的 counter profile | 结果只对当前命中生效；命中后清除上下文；active 或窗口结束后同一招选择 normal profile |

这些样例同时验证运行时、`MoveTable` 和 Combo Solver 使用同一份 profile 选择规则；任何一端把缺失 profile 当作普通命中，均视为实现错误。最终数值与招式路线在 D 轮另行收敛。

## 2026-09-23：角色招式完整基线（后续确认，覆盖相关历史提案）
